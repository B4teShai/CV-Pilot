# Testing strategy

Tests are written before the code they test. A change without a test that failed first is
not reviewable. Coverage on `src/` must stay at or above 85 %; the number is a floor, not a
target.

## Tiers

| Tier | Location | Proves | Runs |
|---|---|---|---|
| Unit | `tests/unit/` | One function or class behaves per its docstring, including edge cases | every push, all Python versions |
| Contract | `tests/unit/test_*_contract.py` | A cross-cutting contract holds (logging fields, exit codes, settings validation) | every push |
| Golden | `tests/golden/` | A documented input produces a byte-identical or field-identical output (format round-trips, reports, manifests) | every push |
| Parity | `tests/parity/` | A metric or transformation matches a reference implementation within a stated tolerance | every push while fast (the pycocotools suite takes about 15 s; marker `parity`) |
| Chaos | `tests/chaos/` | The system survives interrupted writes, truncated files, killed processes | nightly or on touch |
| Docs | `tests/docs/` | The documentation builds strictly with no remote assets, every command of the tutorial runs and prints what the page says, the generated CLI reference matches the code | every push (the `docs` job also builds the site) |
| Release | `tests/release/` | The wheel and sdist contain exactly what they should (license, NOTICE, `py.typed`, only the documented core dependencies, nothing from the repository), `twine check --strict` passes, the wheel installs and runs in clean environments | every push (the `package` job) |
| Clone | `tests/release/test_clone.py` | A fresh clone of the current commit installs with `pip install .` into a new virtual environment and runs `--version`, `doctor` and the README quick start (`scripts/check_clone.sh`) | manual, `pytest -m clone`; off by default because the dependencies come from the network |
| Smoke | `tests/smoke/` | A real tracker or framework library works with the adapter | manual, `pytest -m real_libs`; off by default (`addopts` deselects the `real_libs` marker), skips when the library is absent, needs no network |
| Benchmark | `benchmarks/` | A performance budget is met on a named reference input | manual, before release |

A tier directory is created the moment the first test of that tier exists; empty
directories are not committed.

## Rules

- Unit tests make no network calls, read no files outside `tmp_path`, and do not depend on
  wall-clock time or environment variables unless the test sets them.
- Test names state the behaviour: `test_redacts_nested_authorization_header`, not
  `test_redact_2`.
- Assert behaviour, not implementation. A refactor that keeps behaviour must not break a
  test.
- Every bug fix adds the test that would have caught it.
- Edge cases are the default checklist: empty input, one element, invalid input, unicode,
  very large input, non-serialisable values, interrupted I/O, concurrent access where
  relevant.

## Fixtures

- Small synthetic fixtures live next to the tests. Anything over 100 KB is generated by a
  script in `tests/fixtures/` at test time.
- Fixtures never contain real personal data, real credentials or real customer images.
  Fake secrets used to test redaction are obviously fake (`"token": "not-a-real-token"`).

## Parity and chaos specifics

- Parity tests pin the reference implementation's version and record the tolerance in the
  test. A tolerance change is a reviewed decision.
- Chaos tests kill real processes with `SIGKILL` inside a save and check that a fresh process
  restores a whole checkpoint and never a partial file. `tests/chaos/test_ckpt_kill_points.py` does
  this 200 times at each of four places inside a save and 200 times at a random moment, from a fixed
  seed (about 2.5 minutes); `test_ckpt_truncated_upload.py` cuts 200 uploads to an in-memory
  filesystem. Chaos tests use temporary directories only and never the user's store or cache.

## What CI runs

```bash notest
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=cvpilot --cov-fail-under=85
```

Chaos and benchmark tiers are selected with pytest markers (`-m chaos`). The parity tier
(`-m parity`, about 40 s with 465 cases) is fast enough to stay in the default run and in CI.
