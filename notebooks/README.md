# Notebooks: CV-Pilot on real data and real models (outputs saved from a real run)
`01_tutorial.ipynb`: doctor, record a run, score YOLO11n on COCO128 per class, pin a baseline, compare and gate a worse candidate, CI, kill and resume a training job.
`02_edge_cases.ipynb`: 39 checked cases (bad inputs, fail-closed gates, edited results, damaged or tampered checkpoints) ending in an expected-vs-actual table.
`03_alerts_and_hf_trainer.ipynb`: a real ResNet-18 from the Hugging Face Hub fine-tuned with the `Trainer` and the CV-Pilot hook; an injected NaN loss, a plateau and a real regression send alerts to a local listener (messages shown); step time with dead channels; `cvpilot alerts check`.
`04_real_checkpoints.ipynb`: the files frameworks really write (Lightning `.ckpt`, Ultralytics `last.pt`, a Hugging Face Trainer folder, an MMEngine `.pth`) from real short training runs: which the strict reader takes or refuses (exact messages), verify, tamper (flip, truncate, swap), resume with identical weights where the framework allows, and what a save costs on real model sizes.
`05_chaos_and_rfdetr.ipynb`: 1,000 `SIGKILL`s inside checkpoint saves and 200 cut uploads, each restart checked byte for byte; RF-DETR Nano (Apache-2.0, licences checked before the pinned download) fine-tuned on COCO128 photos with the hook, compared with the framework's own metrics file.
Data: COCO128 (128 photos; annotations CC BY 4.0, images keep their Flickr licences). Models: YOLO11n via `ultralytics` (AGPL-3.0, extra `cvpilot[ultralytics]`), a small PyTorch classifier, `microsoft/resnet-18` (Apache-2.0, pinned Hub commit, safetensors) and RF-DETR Nano (Apache-2.0, 366 MB, notebook 05 only). All downloads (SHA-256 pinned, checked before unpacking or loading) go to `$CVPILOT_NOTEBOOK_DATA` (default `~/.cache/cvpilot-notebooks`, created with mode 0700; a folder that is a link, belongs to someone else or is writable by others is refused), never into the repository; the internet is needed once.
Run from the repository root; nothing is added to `pyproject.toml` or `uv.lock` (notebook 04 needs the `lightning` and `mmengine` extras too, notebook 05 the `rfdetr` extra): `uv run --extra hf --extra lightning --extra mmengine --extra safetensors --extra remote --with jupyterlab --with ipykernel --with matplotlib --with ultralytics --with torchvision --with pycocotools jupyter lab notebooks`
To re-execute and save the outputs: `uv run <same options> --with nbclient python -c "import nbformat; from nbclient import NotebookClient as C; n = nbformat.read('notebooks/03_alerts_and_hf_trainer.ipynb', 4); C(n, timeout=3000).execute(); nbformat.write(n, 'notebooks/03_alerts_and_hf_trainer.ipynb')"` (or `jupyter nbconvert --to notebook --execute --inplace`).
Each notebook starts in a fresh temporary folder with its own empty store; on a laptop CPU 01 takes about 1 minute, 02 about 1.5, 03 about 10, 04 about 1 and 05 about 4 (plus a 366 MB download once). Notebook 02 reuses the detections that 01 cached, and 03 does too. The notebooks are not part of the wheel or the sdist; `tests/notebooks` checks them without running anything.
